# V0 邮箱密码认证设计

**日期**：2026-09-09  
**状态**：已确认，准备实施  
**范围**：V0 自有账号认证；微信、QQ 和其他第三方登录保留到 V2

## 目标

为 Vue + FastAPI 应用提供可持续使用的邮箱密码注册、登录、当前用户查询、令牌刷新和登出能力，并为后续所有用户资源提供统一的身份和用户隔离依赖。

## 认证策略

- 用户使用邮箱和密码创建本地账号。
- 邮箱在应用层去除首尾空白并转为小写，数据库继续以唯一约束兜底。
- 密码使用 Argon2id 哈希；数据库只保存 `password_hash`，不保存明文密码。
- Access Token 使用 JWT，默认有效期 30 分钟，包含 `sub`、`type`、`iat`、`exp` 和唯一 `jti`。
- Refresh Token 使用高熵随机字符串，默认有效期 30 天；服务端只保存 SHA-256 哈希到 `auth_sessions.token_hash`。
- Refresh Token 刷新时轮换原会话：原会话立即撤销并创建新会话，避免同一个刷新令牌长期复用。
- 登出只撤销当前刷新会话；密码修改、账号停用等后续功能可撤销该用户全部会话。

## API 契约

### `POST /api/v1/auth/register`

请求：`{ "email": "user@example.com", "password": "..." }`

响应 `201`：用户摘要、Access Token 和 Refresh Token。邮箱已存在返回 `409`。

### `POST /api/v1/auth/login`

请求与注册一致。成功返回同一认证响应；邮箱不存在、密码错误和停用账号统一返回 `401`，不暴露账号存在性。

### `POST /api/v1/auth/refresh`

请求：`{ "refresh_token": "..." }`。检查哈希匹配、未撤销、未过期和用户状态，成功轮换会话并返回新的认证响应；失败返回 `401`。

### `POST /api/v1/auth/logout`

请求：`{ "refresh_token": "..." }`。对不存在、已撤销或已过期令牌保持幂等，成功返回 `204`。

### `GET /api/v1/auth/me`

请求头：`Authorization: Bearer <access_token>`。验证 JWT、用户状态并返回用户摘要。

## 错误和隔离

- 请求格式不合法返回 `422`。
- 认证失败统一使用 `401` 和稳定错误码，不返回密码校验细节。
- 注册冲突返回 `409`。
- 所有受保护接口通过 `current_user` 依赖取得用户，业务查询必须使用该用户 ID，不信任客户端传入的用户 ID。
- JWT 密钥、算法和时长由环境变量配置；生产环境必须使用高熵密钥并通过 HTTPS。

## 数据库

继续复用 `users` 和 `auth_sessions`。本阶段不新建认证表；为 `auth_sessions` 增加会话更新时间和令牌类型字段时，必须通过独立 Alembic 迁移完成。若现有字段足以支撑刷新轮换，则只新增必要索引或保持现有表结构。

## 测试验收

- 注册成功且密码只以哈希保存。
- 重复邮箱返回 `409`，大小写和首尾空白按同一邮箱处理。
- 正确密码登录成功，错误密码和未知邮箱均返回相同 `401` 类错误。
- 停用账号不能登录或刷新。
- JWT 可访问 `/me`，过期、错误签名和错误类型不能访问。
- Refresh Token 可刷新一次；轮换后旧令牌不能再次刷新。
- 登出后刷新令牌失效，重复登出不报错。
- 两个用户的令牌不能读取对方资源；认证依赖拒绝缺失或错误 Bearer 头。
