# V0 首次登录分层问卷与饮食画像评估设计

**日期**：2026-09-09
**状态**：设计已确认，待实施
**范围**：注册后首次登录引导、快速建档、可续填 FFQ、确定性基线结果、画像确认与安全联动

## 1. 目标与边界

用户首次登录时可以选择快速建档、完整评估或跳过。快速建档提交后立即得到一份简短结果；用户可直接进入产品，也可继续答题获取详细评测。退出答题后，下一次从上次进度继续，已经回答的问题不会重复出现。

本功能的目标是减少错误推荐、逐步建立可授权的用户画像，并帮助用户决定一个可执行的下一步。它不诊断疾病、不推断营养素缺乏、不提供药物或治疗建议，也不在 V0 计算精确热量和营养素。

评分统一称为“饮食与生活方式基线分”，表示用户自填行为信息与项目规则的匹配程度，不是健康分、体质分或疾病风险分。危险症状、特殊人群、疾病和用药不参与普通加减分，只产生独立安全标签和受限处理。

## 2. 用户流程

```text
注册成功或首次登录
  -> 查询当前用户是否已有已完成的快速建档
  -> 无：展示快速建档 / 完整评估 / 暂时跳过
  -> 快速建档：回答 quick 层题目，保存草稿
  -> 提交：计算覆盖度和简短结果
       -> 直接开始使用：进入工作台
       -> 继续详细评测：只展示尚未回答的 standard/full 层题目
  -> 后续：画像页可继续、重做或删除自己的问卷记录
```

跳过不影响聊天、饮食记录或一日方案的基本使用；系统只给出通用建议，并在需要时展示非阻塞的“补充画像可提高建议贴合度”入口。问卷每页必须提供返回、暂存退出、跳过当前题和敏感信息用途说明。

## 3. 问卷层级与结果

同一版本的问卷题库按层级组织，而不是维护三套相互独立的问卷。

| 层级 | 题量目标 | 内容 | 结果 |
|---|---:|---|---|
| `quick` | 15-25 | 目标、饮食限制、饮食规律、活动作息、少量核心食物组 | 覆盖度、基础行为提示、1 个优先行动 |
| `standard` | 35-50 | `quick` 全部内容加食物组频率和饮食行为 | 基线分、维度解释、1-3 个行动方向 |
| `full` | 60-100 | `standard` 全部内容加较细的 FFQ、外食、补充剂和执行条件 | 详细评测、证据链、7 天行动建议 |

`quick` 的题目是后续层级的子集。继续评估时，后端按同一提交记录中的已答题目过滤，只下发未答且适用的题目。用户选择不适用或跳过的题目不扣分，但会影响覆盖度。

快速结果只包含：已完成程度、已具备的一个优势、一个最优先改善方向、与该方向直接相关的自填依据，以及继续评估或开始使用的入口。覆盖度低于 60% 时不展示总分；60%-79% 标注“初步评估”；80% 及以上才展示相应层级的完整结果。

## 4. 模块边界与数据流

新增 `assessment` 模块，保持模块化单体，不让问卷直接侵入 `profile`、`safety` 或 Agent。

```text
assessment
  模板、题目、草稿、答案、确定性评分、覆盖度、报告快照
      -> 候选画像事实（pending，含来源和授权意图）
profile
  用户确认后保存 confirmed 长期事实；控制用途授权和记忆开关
safety
  评估敏感答案，返回安全标签或阻止普通流程；不改变行为分数
conversation / diet / plan
  只读取 confirmed 且授权有效的事实；可读取最新已完成评估的最小摘要
```

- `assessment` 不直接写入 `health_facts`。它先返回候选事实，例如目标、偏好、忌口或执行条件。
- `profile` 负责用户确认、撤回、修改、记忆关闭和用途授权。关闭记忆后不能新建候选事实的长期副本，也不能向 Agent 提供已有长期事实。
- `safety` 对急性症状、高敏感疾病/用药、孕哺期、未成年人和严重过敏执行现有的高/中风险规则或新增结构化规则；问卷不应让用户误以为完成后得到医疗结论。
- `conversation`、`diet`、`plan` 不读取原始 FFQ 答案。它们可使用确认事实，以及 `assessment` 提供的非敏感摘要，例如“早餐规律性待改善”，并且每次按任务裁剪上下文。

## 5. 数据模型

问卷原始数据独立保存，避免 `health_profiles.profile_data` 变成不可版本化的大 JSON。所有用户资源均带 `user_id`，仓储查询必须接收该参数。

| 表 | 核心字段 | 责任 |
|---|---|---|
| `assessment_templates` | `id`、`code`、`version`、`status`、`target_population`、`published_at` | 发布后的问卷版本，不允许原地改写历史规则 |
| `assessment_questions` | `template_id`、`code`、`tier`、`section`、`answer_type`、`options_json`、`scoring_rule_json`、`safety_rule_json`、`required`、`sort_order` | 题目、选项、适用条件和结构化规则 |
| `assessment_submissions` | `user_id`、`template_id`、`status`、`highest_tier_completed`、`coverage`、`baseline_score`、`result_json`、`submitted_at` | 某个用户对一个版本的一次可续填答卷 |
| `assessment_answers` | `submission_id`、`question_id`、`answer_json`、`answer_status`、`score`、`answered_at` | 单题答案、跳过/不适用状态和可追溯得分 |
| `assessment_fact_candidates` | `submission_id`、`user_id`、`fact_type`、`value_json`、`sensitivity`、`status`、`consent_required` | 从问卷抽取但尚未进入长期画像的候选事实 |

提交状态固定为 `draft`、`completed_quick`、`completed_standard`、`completed_full`、`superseded`、`deleted`。单题状态固定为 `answered`、`skipped`、`not_applicable`。报告保存为结果快照，并包含模板版本、规则版本、覆盖度、分数和建议证据，确保未来改题后旧报告仍可解释。

## 6. 评分、报告与安全

初版只做确定性计算。每道可计分行为题按结构化规则得到 0-4 分，四个维度按权重汇总：饮食结构与多样性 40%、饮食行为 20%、活动与作息 20%、目标可执行性 20%。维度得分按已回答且适用题目的最高可得分归一化，跳过题不按 0 分计算。

```text
维度分 = 已回答适用题的实际分数 / 已回答适用题的最高分 * 100
基线分 = 饮食结构 * 0.40 + 饮食行为 * 0.20 + 活动作息 * 0.20 + 可执行性 * 0.20
覆盖度 = 已回答且适用的计分题数 / 适用计分题数 * 100
```

每条报告建议必须保存 `recommendation_code`、触发规则、来源题目代码、用户选项、模板版本和规则版本。AI 可以在以后将已验证的结果改写为易读文字，但不得修改分数、覆盖度、安全标签或建议依据。

安全题必须显示独立用途说明和“不保存”选项。急性危险线索直接给出固定安全提示；其他敏感答案只在用户明确授权后才能创建长期事实。报告只能说明“根据你的自填信息”，不能声称诊断、治疗、风险预测或疗效。

## 7. API 契约

所有接口通过登录令牌取得当前用户，不接收客户端传入的 `user_id`。写操作支持 `Idempotency-Key`，重复请求返回首次结果，不重复创建答案或报告。

| 接口 | 用途 |
|---|---|
| `GET /api/v1/assessments/onboarding` | 返回当前用户的引导状态、可选入口与可恢复草稿摘要 |
| `POST /api/v1/assessments/submissions` | 以指定模板版本创建或恢复一份草稿 |
| `GET /api/v1/assessments/submissions/{id}/questions?tier=...` | 返回当前层级未答且适用的题目 |
| `PUT /api/v1/assessments/submissions/{id}/answers/{question_code}` | 新增、修改或标记跳过单题答案 |
| `POST /api/v1/assessments/submissions/{id}/complete` | 校验层级、计算结果、生成候选事实和报告快照 |
| `GET /api/v1/assessments/submissions/{id}/result` | 获取可解释的简短或详细结果 |
| `POST /api/v1/assessments/submissions/{id}/fact-candidates/{id}/confirm` | 通过既有 profile 授权流程确认单个长期事实 |
| `POST /api/v1/assessments/submissions/{id}/supersede` | 开始新版复测，旧提交保留为历史 |
| `DELETE /api/v1/assessments/submissions/{id}` | 删除用户自己的问卷原始数据和结果，保留必要审计摘要 |

## 8. 前端体验

认证成功后，前端调用引导状态接口。无快速结果时显示非强制引导页；已跳过或已有结果时，直接进入工作台，并在画像页保留继续评估入口。快速结果页必须有“开始使用”和“继续详细评测”两个同等级按钮，不能用恐吓式文案阻止跳过。

问卷应按一题或一组紧密题目分页，稳定显示进度、层级、暂存状态和返回操作。进度表示已浏览/已完成的题目比例，不能与健康分混淆。敏感问题单独分组，先展示用途与保存选择，再收集答案。

## 9. 错误处理与测试

- 模板不是 `published`、题目不属于提交版本、选项非法、数值超界或多选超限时返回稳定的 422 错误码。
- 不能读取、修改、删除其他用户的提交、答案、候选事实或报告。
- 提交被中断时已保存答案保持草稿状态；计算失败不把半成品结果标为完成。
- 同一版本和同一答案必须得到相同的分数、覆盖度、建议证据和安全标签。
- 覆盖度低时不生成总分；跳过题不扣分但降低覆盖度；安全标签不参与普通扣分。
- 关闭长期记忆后，候选事实不可确认，已有事实不进入对话/方案上下文；问卷原始数据的保留与删除按用户授权和删除流程处理。
- 前端端到端测试覆盖快速完成、直接使用、草稿续填、从快速无重复升级到标准、跳过、敏感题拒绝保存和高风险固定提示。

## 10. 实施顺序与非目标

1. 先编写并经专业审核 `quick` 题库、选项、份量说明、评分规则和安全题用途文案。
2. 实现模板/题目/提交/答案/候选事实模型、迁移、用户隔离和草稿接口。
3. 实现无模型依赖的评分、覆盖度、证据链和简短结果接口，并完成单元与 API 测试。
4. 接入画像确认、记忆开关、安全规则和最小上下文摘要。
5. 实现首次登录引导、答题页、结果页和续填体验，再做端到端验证。

V0 不包含专业验证的医学量表、自动诊断、精确营养素计算、周期趋势、周报/月报、推送提醒、A/B 实验平台、人工营养师协作或模型自行修改评分。完整 FFQ 的具体题目和评分阈值在编码前必须由具备相应资质的营养专业人员审核。
